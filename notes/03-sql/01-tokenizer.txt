Tokenizer
===
string → tokens → struct
Перед обработкой SQL-строку необходимо преобразовать в программные данные. Например:
```
select a,b from t where c=1;
```
Будет представлено следующим образом:
```
StmtSelect{
  table: "t",
  cols: []string{"a", "b"},
  keys: []NamedCell{{column: "c", value: Cell{Type: TypeI64, I64: 1}}},
}
```
SQL похож на английский язык, но имеет свои собственные слова и грамматику. В языках программирования слова называются токенами. Перед грамматическим анализом строка разбивается на токены. Этот шаг называется токенизацией или лексическим анализом.
Токены SQL можно сгруппировать следующим образом:
- Ключевые слова: select, from и т. д.
- Имена: имена таблиц, имена столбцов и т. д.
- Символы: =, и т. д.
- Числа, строки и т. д.
Каждый тип имеет свои правила и кодируется в разных функциях
---
Архитектура в Rust:
```
SQL string
   ↓
Parser (cursor over &str)
   ↓
tokens / values
   ↓
StmtSelect / StmtInsert / ...
```
---
Синтаксический анализатор(Syntax Parser)
Большинство методов анализа работают путем обработки токенов слева направо и построения структур данных.
Поэтому необходимо отслеживать текущую позицию в строке
```rust
pub struct  Parser<'a> {
  buffer: &'a [u8],
  position: usize,
}
impl<'a> Parser<'a> {
    pub fn new(s: &'a str) -> Self {...}}
```
---
Имена для разбора (имена таблиц, имена столбцов)
```rust
impl<'a> Parser<'a> {
    pub fn try_name(&mut self) -> Option<String> {...}}
```
Требования:
- Пропускать начальные пробелы
- Первый символ - буква или _, последующие символы - буквы, цифры или _
- В случае успеха вернуть true и перейти на следующую позицию
- В случае неудачи вернуть false и сохранить позицию

вспомогательные функции:
```rust
fn is_space(ch: u8) -> bool
fn is_alpha(ch: u8) -> bool
fn is_digit(ch: u8) -> bool
fn is_name_start(ch: u8) -> bool
fn is_name_continue(ch: u8) -> bool
```
---
Анализ ключевых слов(Parse Keywords)
```rust
impl<'a> Parser<'a> {
    pub fn try_keyword(&mut self, kw: &str) -> bool {...}}
```
Требования:
- Пропускать начальные пробелы
- Сопоставлять ключевое слово без учета регистра. В случае успеха переходить на следующую позицию и возвращать true
- В противном случае возвращать false
- Ключевые слова должны быть разделены пробелом или знаком препинания

Для определения разделителей:
```go
fn is_separator(ch: u8) -> bool
```

====
```rust
matches!(ch, b'\t' | b'\n' | b'\x0B' | b'\x0C' | b'\r' | b' ')
```
Проверяет:
ch — это какой-то whitespace-байт?
---
| Запись    | Что это              |
| --------- | -------------------- |
| `b' '`    | пробел (space)       |
| `b'\t'`   | таб (tab)            |
| `b'\n'`   | перевод строки (LF)  |
| `b'\r'`   | возврат каретки (CR) |
| `b'\x0B'` | vertical tab         |
| `b'\x0C'` | form feed            |
*ASCII-пробельные символы

b'X' это байтовый литерал (u8), а не char
Пример:
```rust
let ch: u8 = b' ';
```

matches! проверяет
```rust
ch == b'\t'
|| ch == b'\n'
|| ch == b'\x0B'
|| ch == b'\x0C'
|| ch == b'\r'
|| ch == b' '
```
Возвращает bool
Аналог:
```rust
ch.is_ascii_whitespace()
```
